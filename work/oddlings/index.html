Overview

ONE is a small site with two original puzzle games. ONE Classic is a daily 3×3 visual-reasoning puzzle; ONE Oddlings is the faster, more playful one. Circle, Square, Triangle and Diamond stand on a board that breaks its goal in exactly one place. One swap fixes it, the next board drops in, and a five-minute run asks how many you can fix.

The problem

Most casual puzzle games either hand-author a few hundred levels or generate boards that are occasionally unfair. I wanted endless, genuinely fresh boards that are always solvable, that get harder as you improve, and that never use dark patterns to keep people playing.

Why it mattered to me

Games are the most honest product test there is: if it isn't fun in the first ten seconds, nobody stays. It also let me combine algorithms, interaction design, motion and sound in one product.

My role

  • Game design: rules, goals, pacing, scoring, praise, the daily run and streaks.
  • Engineering: board generator, independent verifier, adaptive skill model, input (tap, drag and keyboard), sound and motion.
  • Character art direction and asset pipeline: sprite QA scripts, measured eye contours for blinks, right-sized WebP copies.
  • Quality: unit, replay and end-to-end tests; accessibility and reduced-motion support; release gates.

Architecture

Hard problems

01Every board must be fair

The generator builds a finished picture, then breaks it with one swap. That is not enough on its own: a bug could still ship an unsolvable board. A separate checker re-reads each board as literal rows and columns — no gameplay helpers — and confirms at least one swap satisfies the visible goal. Any swap that satisfies the goal is accepted, not just the generator's. A quality script builds 500 runs of 40 boards (20,000) and re-checks every one; the last run had zero failures.

02Difficulty that adapts without being creepy

Free runs adapt to the player using an on-device skill model in the style of Glicko: one ability estimate per kind of goal, each with its own uncertainty, and a logistic chance of a clean solve. Nothing about time spent, purchases, device or account influences a choice. Daily runs never adapt, so everyone gets the same boards.

03Measuring how much novelty really exists

A stress test built 110,000 candidate boards and counted repeats at three strengths: exact boards, look-alikes (the same layout with shapes renamed) and structures (the same solving logic under the goal's own symmetries). Most goals have only two to seven genuinely different structures, which proved that real variety has to come from mixing goals — and changed the roadmap.

04Links that never change what they replay

Runs are seeded and versioned (v=1, v=2, v=3). A digest of 6,000 boards pins older schedules in a replay test, so a friend's challenge link always rebuilds the exact boards it was shared with.

Testing & reliability

The ONE repository has 150+ test files and roughly 1,100 unit and end-to-end cases, including replay tests that pin old board schedules, a 20,000-board quality run, sprite QA (alpha, halos, framing and a shared foot line for all 20 sprites) and an art manifest check that fails the build if a web copy goes stale. End-to-end tests run in Chromium, with Firefox and WebKit available.

Results

  • Both games are implemented on the main branch; Oddlings is in the preview build.
  • Zero failures across 20,000 generated boards in the latest quality run.
  • Keyboard, drag and tap input; reduced-motion and dark-theme support; sound off by default.

Lessons

  1. If the rules are the product, check them twice — with two pieces of code that don't share assumptions.
  2. Measure novelty before promising it. The stress test changed the roadmap more than any opinion did.
  3. Game feel is engineering: tick marks on settled pieces, a draining time bar and a rising pitch for each fix in a row made the biggest difference.
