## Architecture decision

**Kept:** static files served by GitHub Pages from `master`, no backend, no recurring cost.

**Changed:** the 15 hand-maintained HTML files (each duplicating the header, footer and facts) are now generated by `src/build.mjs` from `src/data/*`. It is ~100 lines with zero runtime dependencies; templates use a tagged `html` function that escapes by default.

**Rejected:**
- *Astro / Next.js* — good fits for content sites, but would need a CI build-and-deploy pipeline (the account's GitHub Actions minutes have been unreliable elsewhere) or a change of Pages source, adds hundreds of dev dependencies, and buys little over what 100 lines of Node do here.
- *React SPA* — client rendering hurts LCP and crawlability for a content site.
- *GSAP / Lenis / Three.js* — the motion needed (line-draw, reveals, pulses) is achievable with CSS transitions, SVG `stroke-dashoffset`, IntersectionObserver and the View Transitions API at ~6 KB of JS. No scroll hijacking.
